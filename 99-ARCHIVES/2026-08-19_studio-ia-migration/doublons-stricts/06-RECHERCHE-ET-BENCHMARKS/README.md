# Recherche et benchmarks — règle d’exploitation

## Cockpits HTML archivés

1. `01-Julia-Roga-benchmark.html` — création technologique, univers visuel et terminologie propriétaire.
2. `02-Imane-Oubou-benchmark.html` — architecture humain/avatar, formation, produits et funnel.
3. `03-Allie-K-Miller-benchmark.html` — autorité, distribution, formation et audience propriétaire.

Ces fichiers sont les sources complètes. Les décisions stratégiques doivent être consignées séparément afin de préserver les analyses originales.

Un benchmark n’est jamais conservé seul. Chaque étude doit contenir deux blocs :

## 1. Données observées

- source et date ;
- positionnement ;
- audience ;
- offre et prix ;
- mécanismes de contenu ;
- preuves ;
- limites et éléments non vérifiés.

## 2. Analyse d’exploitation pour PROD’AI

- ce que l’information confirme ou invalide ;
- ce qui est transférable à PROD’AI Lab ;
- ce qui est transférable à PROD’AI Academy ;
- ce qui ne doit pas être copié ;
- impact sur le positionnement, l’offre ou le funnel ;
- décision proposée ;
- test nécessaire avant adoption.

## Synthèse actuelle

- **Julia Roga** : retenir le code visuel, la terminologie propriétaire et la mise en scène lifestyle; ne pas copier une autorité déjà acquise.
- **Imane Oubou** : retenir la transparence humain/avatar et la double économie média/formation; ne pas diviser prématurément une petite audience en deux comptes.
- **Allie K. Miller** : retenir la distribution, la liste propriétaire et la formation comme aval de l’autorité; ne pas réduire AI Lab à une activité de formatrice généraliste.

Conclusion : la différenciation de PROD’AI vient des cas réellement construits et du passage **expérience → méthode → service → formation**, pas d’un catalogue d’outils.
